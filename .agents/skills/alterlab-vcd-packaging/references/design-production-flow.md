# 包装设计 → 同源3D → 核样文件 → 实物生产


本文件规定跨阶段主链；调研和客户提案细则沿用包装 Skill 的参考，不另造第二套标准。工作台现有六阶段仍是需求、调研、方案、结构、设计、交付；下面的检查嵌入这些阶段，不表示软件新增了自动视觉验收。

## 0. 接续与版本核对

先读 [续作状态](continuation-state.md)，核对当前用户任务、工程文件、工作台项目名/版本及是否有未保存修改。资料不一致先查明或询问，不按文件名最大数字自动覆盖。

每次确定：`案件/分支｜本次任务｜基准文件与内容指纹或SHA-256｜用户已确认范围｜本次改动｜当前检查｜下一步`。

新设计从阶段1开始；既有工程修订只重开相关阶段。非设计的软件修复先读接续信息，再按代码变更范围执行，不强制重做调研、A/B或客户方案。

## 1. 需求与结构条件

记录产品、卖点依据、购买/使用场景、品牌、准确文案、数量、尺寸类别、盒型、材料及已确认工艺。区分产品尺寸、盒内径和盒外径；没有实测就保留假设，不能声称装得下。

- 已确认、建议、假设和待确认分别记录；仅询问影响当前决策的缺口。
- 不能从参考图照搬无依据的功效、认证、奖项或材料声称。
- 结构坐标从 `geomOf` 和当前模板推导；纸厚、插口、装入余量和结构白样另行核验。

**产物**：案件设计说明和工作台 `meta.workflow` 中适用字段。不能用“需求已录入”代替尺寸/产品资料验收。

## 2. 调研、概念与选款

按包装 Skill 的 `research-and-selection.md` 和 `prework-workflow.md` 执行。先写设计判断，再检索；实际查看参考图片，记录来源、日期、采用/改造/淘汰及理由。概念作品、实际量产证据和产品使用场景分别判断。

- 新设计交图文研究板；用 `check-research.mjs` 检查资料完整性。该脚本不会判断审美、人体或持物是否正确。
- 展示两套有实质差异的45°选款图，采用相同盒型、尺寸、背景与相近灯光；明确其是否只是概念。
- 选款确认绑定具体版本。已有选款或自主决定授权直接沿用，局部工程修复不重做 A/B。

**门槛**：方向已选，或用户已明确授权自主决定；不存在尚未解决的关键参考缺口。概念图确认不是生产母稿确认。

## 3. 生成前的素材预算

对每份源素材只做一次可复用预算：

`素材ID｜来源/授权｜原始文件及哈希｜最大使用毫米尺寸｜裁剪比例｜实测像素｜有效PPI｜字体/工艺｜重制方法与工具能力｜复用盒面｜检查结果`。

- 当前技术规则是裁剪后的横、纵有效 PPI **均大于300**。不裁剪时，每轴最低有效像素为 `floor(毫米 / 25.4 × 300) + 1`；有裁剪时还要按保留比例反算源像素。
- 纯矢量不按 PPI 判定，但仍要检查形状、最小细节、文字和印刷效果；SVG 内嵌位图仍须查真实精度。
- 生成前确认工具实际可输出的尺寸、用途和连接状态；提示词写“9000像素”不代表工具能做到。结果不达预算时停止沿用相同方法重试，改查源文件、工具能力或经授权重制。
- 共用图案只生成/修复一份源，跨面复用。只改位置、方向、颜色或工艺时不重新生图。
- 字体提前检查真实字体文件、字重、字形覆盖与使用条件；预览和PDF使用同一字体，不静默替字或用错字占位。

**门槛**：预算和工具能力能支撑目标；不能先承诺带光效果图，然后事后才发现整面素材只有56PPI。

## 4. 平面生产母稿与差异复核

先建立实际尺寸、无盒体透视的平面母稿，文字、字标、主图、流线、底色和工艺可分别处理。复杂纹理可采用合格位图，不强制全部矢量化。

- 保留只读原稿和版本。去除环境照明、投影、倒影和模拟加工反光；凝胶插画自身的曲面明暗可以属于印刷画面，不能一刀切成平色。
- 拆图/描摹不等于找回原始图层或缺失细节。矢量重绘也不是无损还原；不得靠变成矢量来掩盖设计已经变化。
- 需要重制时明确方法与差异；若会改变原稿视觉，先获得相应授权，再提供旧/新同尺度对照。**允许重制 ≠ 新结果已获确认**。
- 矢量渲染的高清PNG标为“矢量渲染”，不是AI原生高像素，也不是旧图细节恢复。检查实际输出文件尺寸与生成链，不能只看文件名、DPI标签或插值后的宽高。

**产物**：平面母稿、独立元素、素材记录及新旧对照。技术精度与视觉相似度分别记录，任一未确认不能当作最终设计交付。

## 5. 可编辑工程与真实工艺

复用工程格式、模板几何和分组/套准函数；版本另存，图片内嵌，文字/底色/图案/工艺独立，不能整张展开图压成图片冒充可编辑工程。

|用户确认的要求|必须落入工程的操作|检查|
|普通印刷|`finish=none`、`factoryId=print`，适当版归属|不能另残留同图烫金覆盖|
|烫金|独立白色正图加工层，`finish=foil`、`factoryId=metal`和实际版ID|仅加工应烫的位置，核对细线/镂空|
|凝胶块整版UV、空隙不做|同盒面整版、多个实心块面、间隙留空，`finish=uv`、`factoryId=film`|不是只画外框，也不是整片矩形涂满|
|取消某工艺|移除对应加工层或真实取消加工属性，检查所有复用盒面|不能只改文案、隐藏预览开关，或关闭整盒其它烫金|

覆盖印刷的加工层用 `bindRegistration` 绑定同盒面原图，保持联动。新母稿改变块边界时同步工艺版，检查满面覆盖、间隙、重叠和套准补偿。补偿量、最小线宽等由工厂核样确认，不能凭默认值放行。

**门槛**：工艺属性、版归属、关联与实际范围一致；修改后核对所有实例及实际图层数量。不能只在报告中写“已设置UV”。

## 6. 同源3D、视觉确认与客户方案

工作台3D、正式客户展示和生产导出使用同一母稿、同一坐标及工艺版，不另生成一张AI盒子图冒充工程效果。

- 根据真实折叠关系检查正、背、左、右、上、下；确认整盒立放/平放。特别检查背面和侧面是否旋转180°，同步旋转印刷与工艺，复查套准。
- 用户要求正背相同/双侧相同时，复用同源图形，不分别重新生成。3D灯光导致的明暗不同先查材质、相机和贴图字节，不擅自改两面印刷亮度。
- 逐项对照轮廓、块数/分布、纹理方向、流线、字体、Logo比例、文字、六面方向及工艺覆盖。原尺寸细节和整体观看均检查；保存实际截图与差异。
- 用户确认的是具体版本及范围，既有确认继续有效。修改图案、尺寸、位置、工艺或材质后复核受影响项，不复制旧版验收记录。
- 正式客户方案遵循 `proposal-workflow.md`，使用同源3D和静态后备图；客户已缩减板块时遵循本案范围。使用场景单图先审后排版，不把技术测试报告充当客户设计理念。

**门槛**：具体视觉版本已确认后正式交接工作台。用户明确要求工程测试/核样时可载入候选稿，但标明待核验，不能据此记录视觉通过。

## 7. 保存、重开与两级导出

载入前核对浏览器项目标题和文件版本；保存到项目库后核对成功提示。重开核对版本、素材、方向、工艺和检查状态；保留旧版及未保存页面。不能只发一个链接就声称已导入、保存和验证。

先运行真实源文件预检，再在浏览器检查实际图像加载与检查明细：

```powershell
node scripts/project-preflight.mjs "drafts/实际工程.boxproj"
node scripts/project-preflight.mjs "drafts/实际工程.boxproj" --production
```

当前CLI不带参数时输出技术问题和待核验信息，不以退出码0判断通过；带 `--production` 时，只要技术问题或四项核验未齐就以非零退出。核样是否可导出应看技术问题是否为0，不能为了通过CLI伪造四项验收。

|交付入口|允许条件|含义|
|工程备份 `.boxproj` / 评审PDF|允许保留未解决问题，明确状态|供编辑/评审；不是制版文件|
|工厂核样包（禁止量产）|技术检查通过；本版四项可尚未核验|供工厂试开、RIP和打样；不能跳过低精度|
|生产文件包|技术通过 + 本版视觉/工艺/结构/工厂四项真实核验|进入生产交接，仍受工厂实际控制|

技术问题亮红；未核验/记录失效亮黄。绿灯只代表该项有依据。“0项技术红灯、4项待核验”不是整体合格；不能删除门槛、改布尔值或填假凭据让按钮变亮。

当前工作台工艺/印刷包实际固定包含：`印刷层.pdf`、`工厂一工艺层.pdf`、`工厂二工艺层.pdf`、`reference/dieline.svg`、`交付说明.txt`、`manifest.json`。空工艺组仍有空白母版，须说明；工艺母版有多个版时，制版前仅启用所需版。

`.boxproj` 是另行备份的可编辑工程，不是PDF。用户要完整交付时同时提供同版工程备份；若另打总ZIP，核实其真正包含这些文件。刀线PDF并非当前标准包默认产物，需要时明确另制、同源核对，不能谎报包内已有。

## 8. 实际文件复核与工厂核样

导出后检查**实际下载的最终文件**，而不是仅检查JS对象或预览图：

1. 解压ZIP，核对文件清单、SHA-256、JSON可解析及工程能重开；不要用经工具截断的大段data URL/base64替代原始文件传输。
2. 解析三份PDF的实际毫米尺寸、共同原点/比例、页面框、原生图层、版别、素材归属、字体、位图有效PPI及缺图情况。1:1和页面出血框不证明实际图案已出血。
3. 渲染PDF再目视核对，检查裁切、方向、文字、颜色、块面、间隙和工艺范围。刀线若单独制PDF，还要核对真实坐标与全版范围，不能把mm误当px/pt后放大裁切。
4. 对照同一工程回贴3D。新改动后只重查受影响范围；没有新变化和失败，不重复生成或无目的重复测试。
5. 由真实工厂试开、RIP、结构白样、纸张/颜色/箔材/UV实物核样；记录本版凭据与结果。软件自测、研究案例或“文件可解析”不能代替这些结果。

当前导出为CMYK数值转换，不能称为已通过ICC/PDF-X认证。没有工厂结果就保持待核验，不给“可直接量产”的结论。

## 交接记录与异常处理

每次发生实质变更，更新案件记录及 [续作状态](continuation-state.md)，采用：

`版本/文件/哈希｜本次范围｜源素材与最大尺寸｜工艺和关联｜技术检查｜视觉差异及确认范围｜保存/重开/下载事实｜阻断或待核验｜下一步`。

工具能力不符、缺高清源、连接失效、图形与原稿不符或文件验证失败时，明确具体问题、已完成部分及最小下一步。不要重复同尺寸生图、隐藏红灯、替换设计后自动算通过，或把“已尝试”报告为“已完成”。

## 程序检查的真实边界

- `src/design/productionCheck.js`：素材精度、比例、加载、字体接入及套准等技术问题。
- `src/design/acceptance.js`：四项人工凭据与工程指纹绑定、修改后失效；不是不可伪造的工厂签名，也不自动识别画面一致性。
- `src/ui/OutputView.jsx`、`src/ui/deliveryTask.js`、`src/export/productionBundle.js`：核样/正式导出的UI、执行和导出门槛。
- `src/export/verifyProduction.js`：实际PDF结构、页面、图层和位图精度检查；不代替目视和工厂核样。

本流程约束代理执行，复用现有程序阻断；不声称已经把所有文字规则实现为自动检测。不能承诺AI绝不犯错，必须保留可核对的证据和退回路径。
